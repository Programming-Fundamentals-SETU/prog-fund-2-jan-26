## Exercise 1 -- Spot the Difference (Abstract vs Concrete)

Consider the following two class declarations:

``` java
public abstract class Animal {
    public abstract void makeSound();
}

public class Dog extends Animal {
    public void makeSound() {
        System.out.println("Bark");
    }
}
```

### Tasks:

1.  Which class is **abstract**?
2.  Can you create an object of `Animal`? Why/why not?
3.  Why is `Dog` considered a **concrete** class?
4.  What would happen if `Dog` did **not** implement `makeSound()`?

## Exercise 4 -- The "Deadly Diamond of Death" (Conceptual)

``` java
class A {
    void doSomething() { System.out.println("A"); }
}

class B extends A {
    void doSomething() { System.out.println("B"); }
}

class C extends A {
    void doSomething() { System.out.println("C"); }
}

// Not allowed in Java
class D extends B, C {
}
```

### Tasks:

1.  What problem occurs in class `D`?
2.  Why can Java not decide which `doSomething()` to use?
3.  Explain why this leads to the "Deadly Diamond of Death".
4.  How does Java avoid this problem?
