# Driver class

The responsibility of the Driver class is to run the app and perform I/O with the user.   

There is starter code for Driver in the Starter Code. 
 
## Menu

The code supplied uses a "layered" menu approach i.e. a suggested main menu that calls suggested sub menus e.g.: 

![](img/menus.png)

Whereas it is suffucient (and mostly expected) It is completely up to you how you would like to design the  Pet Menu and the Reports Menu.  As you design these, you should try use all the methods that are written in DayCare. For example:

- when reporting on the Pets, you have different types of Pets to report on e.g. Cat, etc. 


So, when writing this class, the above menus are just a suggestion.  You may deviate from them as you wish.  If you provide more elaborate menu items/reports, you may need to add more methods to the DayCare class (extra credit!).

If you do deviate from the suggested menus, 

 - ensure that you still include the following basic elements:

    - CRUD on the Pets list
    - Reporting for Pets 
    - Persistence

- ensure that you carefully document any changes from the spec in your readme file.

## A note on I/O
Aside from the ScannerInput class, this class should be the only class that has:

- System.out.print statements
- ScannerInput objects defined/used. (You are given ScannerInput in the starter code - this is the better way to read in from the keyboard.)
